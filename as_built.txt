PURPOSE
Answer "which leads/deals come from Google Ads" from data, power the self-service
"MAG GA4 Agent" tab, and feed the dashboard's "Lead Source Tracking" tab with a
per-AC-contact channel + conversion-action mapping. GA4 gives aggregate Google Ads
volume; reliable per-lead attribution would require a gclid captured into
ActiveCampaign (none exists today).

SCRIPTS (this repo)
- scripts/ga4_routine.py — cloud-friendly GA4 pull. Key from env GA4_SA_JSON_B64
  (base64) | GA4_SA_JSON_CONTENT (raw) | GA4_SA_JSON (path). Args --days,
  --google-ads-only, --limit. Prints a markdown table. Run by the cloud routine.
  Requires: GA4_PROPERTY_ID + a key var.
- scripts/ga4_pull.py — local GA4 report → output/ga4_source_medium_{30,90}d.csv.
  Requires: GA4_PROPERTY_ID, GA4_SA_JSON.
- scripts/ac_check_lead_source.py — one-off AC audit (verdict 2026-10-02: Google Ads
  not identifiable per deal). Requires: AC_API_URL, AC_API_TOKEN.
- scripts/google_ads_auth.py — one-time OAuth to mint a Google Ads refresh token.
  Requires a Desktop OAuth client JSON (secrets/oauth_client.json — not present yet).
- scripts/google_ads_pull.py — Google Ads campaign + gclid pull (NOT usable yet;
  needs a developer token + admin access). Requires secrets/google-ads.yaml,
  GADS_CUSTOMER_ID.
- scripts/map_ga4_ac.py (+ scripts/match_ga4_ac.sql) — LEAD MAPPING (60-day general
  cache). Pulls GA4 form events (minute buckets, Sydney->UTC) + Calendly bookings,
  loads Supabase staging, runs match_ga4_ac.sql to rebuild ga4_ac_contact_source +
  ga4_ac_event_matches. Calendly→AC by EMAIL (exact); GA4→AC by TIMESTAMP (+/-300s,
  bulk bursts >2/min excluded), confidence-scored. Args --days (default 60),
  --tolerance-seconds, --events, --dump. Requires: GA4 key vars, CALENDLY token,
  SUPABASE_DB_URL (but see NOTE — currently blank; written via Supabase MCP instead).
- scripts/map_t1_enquiries.py (+ scripts/match_t1_ac.sql) — T1-SCOPED mapping.
  Reproduces the Data Studio "27 T1 Enquiries by channel" (last 30 days) from the 4
  T1 events (calendly_form_submit, click_to_call, email_link_clicks,
  Form_submission_thankyou_1) and maps them to AC contacts. Calendly channel is taken
  from the GA4 calendly_form_submit session source/medium (time-joined). Writes
  public.t1_enquiry_channels + public.t1_enquiry_contacts. click_to_call /
  email_link_clicks are anonymous (no contact). Args --days (default 30),
  --tolerance-seconds, --dump.
- scripts/ad_search_source.py — derives the GA4 session channel for CALENDLY contacts
  (by timestamp-joining bookings to GA4 calendly_form_submit events) and emits
  email->channel JSON, used to fill ga4_ac_contact_source.channel for calendly rows.
  Args --days (default 60), --out.

DATA STORES (Supabase MAGTestProject)
- public.ga4_agent_requests — one row per GA4 Agent question (id, prompt, status,
  result markdown, …). Migration mirrored in the dashboard repo.
- public.ga4_ac_contact_source — per-AC-contact inferred source (the lead-mapping
  deliverable; backs the dashboard's Lead Source Tracking tab). PK contact_id; cols
  source, medium, campaign, match_method (calendly_email|ga4_time|unmatched),
  confidence, candidate_count, matched_at, time_delta_seconds, and **channel** (the
  full GA4 source/medium, incl. for calendly rows; populated OUT-OF-BAND — see
  CLAUDE.md gotcha; was briefly named ad_search_source). Rebuilt by map_ga4_ac.py.
- public.ga4_ac_event_matches — audit: one row per GA4 form bucket / Calendly booking
  with the contact it tied to. Plus staging ga4_events_staging /
  calendly_bookings_staging (truncated + reloaded each run; shared by both mappers).
- public.t1_enquiry_channels — per-channel rollup of the 27 T1 enquiries (ga4_total,
  per-event counts, ac_contacts_matched, unmappable_count). Built by map_t1_enquiries.
- public.t1_enquiry_contacts — one row per identified T1 lead×channel (channel_source,
  channel_medium, conversion_action, match_method, confidence, …).
  Migrations applied via Supabase MCP: create_ga4_ac_mapping, create_t1_enquiry_mapping.
